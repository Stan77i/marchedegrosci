# ORDRE DE MISSION
## MARCHÉ DE GROS DE CÔTE D’IVOIRE × DIGITAL MOTION SYSTEM

### Mission

Ne conçois pas le **Marché de Gros de Côte d’Ivoire** comme un simple site web de vente de produits agricoles.

Ne le conçois pas non plus comme un catalogue enrichi d’animations.

Conçois-le comme **une infrastructure numérique vivante qui représente, facilite et matérialise les échanges entre l’offre et la demande en Côte d’Ivoire.**

La philosophie fondamentale est :

> **Le marché n’est pas un lieu. C’est une connexion.**

Une personne possède une offre : le marché cherche la demande.

Une personne exprime une demande : le marché cherche l’offre.

Le site doit donc être pensé comme un **organisme numérique** dans lequel circulent :

**PRODUITS → OFFRES → DEMANDES → CONNEXIONS → TERRITOIRES → DISPONIBILITÉS → PRIX → ACTIVITÉ → INTELLIGENCE DU MARCHÉ**

Le design, le motion, le WebGL, la typographie, la lumière, le scroll et les interactions doivent tous traduire cette logique.

---

# I. NE PAS CONSTRUIRE UNE INTERFACE. CONSTRUIRE UN MONDE.

L’utilisateur ne doit pas avoir la sensation de parcourir une succession de blocs HTML.

Il doit avoir la sensation d’entrer dans un système.

Un système qui possède :

- une profondeur ;
- une géographie ;
- une matière ;
- une lumière ;
- une vitesse ;
- une inertie ;
- une activité ;
- des flux ;
- des états ;
- des connexions ;
- des zones de concentration ;
- des périodes de calme ;
- des transformations.

Le site doit sembler **vivant sans être artificiellement animé**.

Chaque mouvement doit avoir une cause.

Chaque réaction doit avoir une conséquence.

Chaque transition doit représenter un changement d’état.

Chaque effet doit avoir une fonction.

---

# II. LA PHYSIQUE DU MARCHÉ

Avant de définir les animations, définir la physique du monde.

Le marché numérique doit posséder une logique physique cohérente.

### Une offre

Une offre est une présence dans le réseau.

Elle possède :

- une matière ;
- une quantité ;
- une position géographique ;
- une disponibilité ;
- un prix ;
- une période ;
- un état.

### Une demande

Une demande est un signal.

Elle cherche :

- un produit ;
- une quantité ;
- une zone ;
- une période ;
- un prix ou une condition ;
- une correspondance.

### Une connexion

Une connexion est un mouvement entre deux points compatibles.

Elle peut être représentée visuellement par :

- un flux ;
- une trajectoire ;
- une onde ;
- une lumière ;
- une ligne ;
- une convergence ;
- une propagation.

Mais jamais par une animation gratuite.

**La métaphore visuelle doit toujours découler du fonctionnement réel du marché.**

---

# III. LA CÔTE D’IVOIRE EST UN ESPACE, PAS UN DÉCOR

Ne transforme pas la Côte d’Ivoire en simple illustration décorative.

Le territoire doit avoir une fonction.

Une région peut être :

- une source d’offre ;
- une zone de demande ;
- une concentration de produits ;
- un point de départ ;
- un point d’arrivée ;
- une zone saisonnière ;
- un espace de circulation.

Une route peut devenir une trajectoire.

Une ville peut devenir un nœud.

Une offre peut devenir un point.

Une demande peut devenir une onde.

Une correspondance peut devenir une connexion.

Le territoire devient ainsi **une partie du système économique représenté par l’interface.**

---

# IV. L’EXPÉRIENCE DOIT ÊTRE UNE CAMÉRA

Ne pense pas uniquement en sections.

Pense en plans.

L’utilisateur entre dans un espace.

La caméra peut :

- avancer ;
- reculer ;
- changer de profondeur ;
- modifier son focus ;
- ralentir ;
- accélérer ;
- traverser une matière ;
- révéler progressivement une information ;
- passer d’une échelle locale à une échelle territoriale.

Le scroll n’est pas simplement :

> section suivante.

Il devient :

> **progression dans le système.**

Une page peut commencer avec une vision globale puis progressivement entrer dans :

**territoire → produit → offre → disponibilité → connexion → action.**

---

# V. HIÉRARCHIE DE PROFONDEUR

Tous les éléments ne doivent jamais être sur le même plan.

Construire une hiérarchie claire.

### PREMIER PLAN

- H1 ;
- produit focal ;
- information critique ;
- CTA ;
- action principale ;
- résultat sélectionné.

### PLAN INTERMÉDIAIRE

- informations contextuelles ;
- cartes ;
- données ;
- images ;
- objets interactifs ;
- offres voisines.

### ARRIÈRE-PLAN

- atmosphère ;
- particules ;
- lumière ;
- environnement ;
- matière ;
- traces de circulation.

### PROFONDEUR EXTRÊME

- brouillard ;
- halos ;
- silhouettes ;
- flux abstraits ;
- éléments presque imperceptibles.

La profondeur doit permettre à l’œil de comprendre immédiatement :

> **où regarder maintenant.**

---

# VI. LE MOTION EST LE LANGAGE DU MARCHÉ

Ne rajoute pas des animations après avoir construit l’interface.

Conçois l’interface **à travers le mouvement**.

Le motion doit permettre de comprendre :

- ce qui vient d’apparaître ;
- ce qui est important ;
- ce qui vient de changer ;
- ce qui est connecté ;
- ce qui est disponible ;
- ce qui est recherché ;
- ce qui est proche ;
- ce qui est en transition.

Le mouvement devient donc une forme d’information.

### Mémoire et signature du motion

Créer quelques moments de mouvement distinctifs, directement liés au marché, à ses produits, à ses territoires ou à ses échanges. Ils doivent rendre l’expérience mémorable sans ralentir les tâches ni se répéter partout.

La réussite ne se mesure pas au nombre d’effets, mais à la capacité de l’utilisateur à comprendre le système, à accomplir son action et à se souvenir d’un ou deux moments significatifs.

---

# VII. LE CURSEUR EST UNE FORCE

Le curseur ne doit pas simplement déclencher un hover.

Il devient une force appliquée au monde.

Selon le contexte :

- attraction ;
- répulsion ;
- profondeur ;
- distorsion ;
- lumière ;
- déplacement ;
- inertie ;
- révélation ;
- influence sur les particules ;
- influence sur la matière.

Exemple :

L’utilisateur approche une zone contenant plusieurs offres.

Les éléments proches réagissent davantage.

Les éléments éloignés restent presque immobiles.

La hiérarchie apparaît naturellement.

Le système donne l'impression que **le curseur possède une masse et influence réellement l'environnement.**

Lorsque le curseur quitte la zone :

le monde revient progressivement à son état naturel.

---

# VIII. LE SCROLL EST UN CONTRÔLEUR NARRATIF

Le scroll peut simultanément contrôler :

- caméra ;
- profondeur ;
- lumière ;
- brouillard ;
- particules ;
- typographie ;
- échelle ;
- position ;
- vitesse ;
- focus ;
- morphing ;
- transitions.

Mais tout doit appartenir à une même timeline.

Exemple :

**CALME**

Le marché respire.

↓

**APPROCHE**

La caméra commence à avancer.

↓

**DENSIFICATION**

Les informations et connexions deviennent visibles.

↓

**FOCUS**

Le produit ou l'information principale devient net.

↓

**RÉVÉLATION**

Les données apparaissent.

↓

**ACTION**

Le système se stabilise pour permettre l'interaction.

Le mouvement raconte ainsi quelque chose.

---

# IX. LA VITESSE POSSÈDE UNE GRAMMAIRE

Tous les éléments ne doivent pas réagir à la même vitesse.

Définir une hiérarchie temporelle.

Certains éléments :

**réagissent immédiatement.**

D'autres :

**suivent avec inertie.**

D'autres :

**restent lourds et progressifs.**

Utiliser intelligemment :

- easing ;
- spring ;
- damping ;
- inertia ;
- friction ;
- velocity ;
- anticipation ;
- overshoot ;
- acceleration ;
- deceleration ;
- settle.

Le monde doit parfois sembler :

- lourd ;
- léger ;
- dense ;
- fluide ;
- rapide ;
- presque immobile.

Cette différence crée la profondeur.

---

# X. LE FLOU EST UNE HIÉRARCHIE

Le blur n'est jamais un simple effet esthétique.

Il sert à déterminer ce qui est :

- proche ;
- éloigné ;
- secondaire ;
- momentanément hors focus ;
- en transition ;
- soumis à une accélération ;
- remplacé par une information plus importante.

Utiliser selon les besoins :

- depth of field ;
- motion blur ;
- directional blur ;
- radial blur ;
- zoom blur ;
- backdrop blur ;
- distortion blur.

Question obligatoire :

> **Qu'est-ce que l'utilisateur doit regarder maintenant ?**

Si le blur ne répond pas à cette question, il est inutile.

---

# XI. LA LUMIÈRE EST UNE FORME DE NAVIGATION

La lumière doit guider l'attention.

Elle peut :

- révéler une offre ;
- isoler un produit ;
- indiquer une connexion ;
- signaler une disponibilité ;
- attirer vers une action ;
- montrer une profondeur ;
- accompagner une transition ;
- matérialiser une activité.

Utiliser si pertinent :

- bloom ;
- rim light ;
- light sweep ;
- volumetric light ;
- halos ;
- illumination progressive ;
- ombres dynamiques ;
- lumière réactive au curseur ;
- lumière contrôlée par le scroll.

La lumière doit rester **élégante, agricole, territoriale et économique**.

Ne pas tomber dans :

- cyberpunk ;
- gaming ;
- néon gratuit ;
- esthétique futuriste générique.

---

# XII. LA MATIÈRE DOIT APPARTENIR AU MARCHÉ

La matière visuelle doit refléter le projet.

Explorer des sensations telles que :

- terre ;
- poussière ;
- brume ;
- lumière ;
- eau ;
- matière organique ;
- grain ;
- verre ;
- surface naturelle ;
- particules ;
- flux.

La matière peut être créée avec :

- shaders ;
- noise ;
- displacement ;
- distortion ;
- Fresnel ;
- reflection ;
- particles ;
- depth ;
- post-processing.

Mais ne jamais utiliser une matière uniquement parce qu'elle est techniquement impressionnante.

---

# XIII. LES PARTICULES DOIVENT REPRÉSENTER QUELQUE CHOSE

Les particules peuvent symboliser :

- matière ;
- poussière ;
- circulation ;
- activité ;
- données ;
- connexions ;
- production ;
- demande ;
- mouvement économique.

Elles peuvent :

- converger ;
- se disperser ;
- suivre un flux ;
- former une structure ;
- disparaître ;
- reconstruire une forme ;
- réagir au curseur ;
- répondre au scroll.

Mais :

> **pas de particules décoratives sans fonction.**

---

# XIV. WEBGL ET DOM DOIVENT ÊTRE LE MÊME MONDE

Ne construis jamais :

> joli canvas WebGL derrière + HTML posé devant.

Le DOM et WebGL doivent communiquer.

Quand un produit apparaît :

- la lumière peut l'atteindre ;
- les particules peuvent converger ;
- la caméra peut se rapprocher ;
- l'environnement peut changer ;
- le texte peut émerger de la profondeur.

Quand une offre est sélectionnée :

- le monde peut se resserrer autour d'elle ;
- les connexions pertinentes peuvent devenir visibles ;
- les autres informations peuvent reculer ;
- la lumière peut changer ;
- la profondeur peut augmenter.

Le WebGL n'est donc pas un arrière-plan.

**Il est une extension visuelle de l'information.**

---

# XV. TYPOGRAPHIE : LE LANGAGE PREND VIE

La typographie reste la principale porte d'accès à l'information.

Elle peut :

- se révéler ;
- se déplacer ;
- se fragmenter ;
- changer d'échelle ;
- traverser la profondeur ;
- se reconstruire ;
- apparaître depuis une matière ;
- devenir immense ;
- disparaître progressivement.

Mais elle doit toujours rester lisible.

Le motion donne une voix au texte.

Il ne doit jamais le rendre incompréhensible.

---

# XVI. LES ÉTATS DU SYSTÈME

Ne créer pas 50 animations indépendantes.

Construire un système d'états.

### IDLE

Le marché respire.

### APPROACH

L'utilisateur approche d'une information.

### FOCUS

Cette information devient dominante.

### INTERACTION

Le système répond.

### REVEAL

Une information supplémentaire apparaît.

### CONNECTION

Deux informations compatibles se rapprochent visuellement.

### TRANSITION

Le système change d'état.

### REST

Le monde revient progressivement à son état naturel.

Ces états doivent contrôler ensemble :

**DOM + WebGL + caméra + lumière + blur + particules + typographie + curseur + scroll.**

---

# XVII. LE CŒUR DU SITE : OFFRE ↔ DEMANDE

Toute la direction artistique doit rester reliée au fonctionnement réel du marché.

## ACHETER — EXPLORER

L'utilisateur arrive avec une intention :

> Je cherche quelque chose.

Le système doit progressivement répondre :

**quoi ?**

→ produit

**où ?**

→ territoire

**combien ?**

→ quantité

**quand ?**

→ disponibilité

**à quel prix ?**

→ prix déclaré / données disponibles

**auprès de qui ?**

→ vendeur

**quelle offre correspond le mieux ?**

→ matching

Le WebGL accompagne cette exploration.

Il ne doit jamais empêcher l'accès rapide aux résultats.

---

# XVIII. VENDRE — CONSTRUIRE UNE OFFRE

La publication d'une offre doit donner l'impression de construire quelque chose.

L'utilisateur renseigne :

**produit → quantité → localisation → disponibilité → prix → conditions**

Chaque information peut enrichir progressivement la représentation visuelle de l'offre.

Mais la forme reste secondaire.

La priorité est :

> **publier correctement une offre réelle.**

---

# XIX. DEMANDER — PROPAGER UN SIGNAL

Une demande n'est pas un formulaire mort.

C'est un signal envoyé au réseau.

L'utilisateur exprime :

**je cherche X**

**dans telle quantité**

**dans telle zone**

**à telle période**

**avec telles conditions.**

Le système peut représenter cette demande comme une onde, une propagation ou une activation du réseau.

Mais uniquement lorsque cela correspond à une action réelle.

Ne jamais simuler artificiellement une réponse du marché.

Si aucune offre n'existe :

> **Aucun résultat ne doit devenir une impasse.**

Le système doit permettre de créer une demande.

L'absence d'offre devient alors une **information de marché**.

---

# XX. CATÉGORIES — EXPLORER LA STRUCTURE DU MARCHÉ

Les catégories ne doivent pas être un simple mur de cartes.

Elles peuvent devenir une structure spatiale :

- constellation ;
- profondeur ;
- familles ;
- regroupements ;
- matières ;
- volumes ;
- relations.

Le curseur peut modifier la profondeur.

Une catégorie peut devenir dominante.

Ses sous-catégories peuvent émerger.

Mais la structure doit rester immédiatement compréhensible.

---

# XXI. CARTE — EXPLORER LE TERRITOIRE

La carte ne doit pas être uniquement géographique.

Elle doit répondre à :

> **Où trouve-t-on ce produit ?**

et progressivement :

> **Où se trouve l'offre ?**

> **Où se trouve la demande ?**

> **Quels territoires sont connectés ?**

> **Où y a-t-il de l'activité ?**

> **Quelle distance sépare les opportunités ?**

La carte devient une représentation spatiale du réseau.

Pas une décoration.

---

# XXII. PRIX DU MARCHÉ — RENDRE LE MARCHÉ LISIBLE

Les prix doivent être représentés avec une rigueur absolue.

Ne jamais transformer le prix déclaré d'un vendeur en « prix du marché ».

Distinguer :

- prix déclaré ;
- fourchette ;
- historique ;
- évolution ;
- comparaison régionale ;
- tendance ;
- tension ;
- abondance ;
- saisonnalité.

S'il n'y a pas suffisamment de données :

> **Données en cours de constitution.**

ou :

> **Pas assez de données pour calculer une tendance.**

Règle absolue :

> **DATA → VISUALISATION.**

Jamais :

> **VISUALISATION → FAUSSE DATA.**

---

# XXIII. LE HEADER EST UNE PORTE, PAS UN TABLEAU DE BORD

Conserver la navigation actuelle :

**Accueil · Acheter · Vendre · Demander · Catégories · Carte · Prix du marché**

Le header doit rester :

- élégant ;
- minimal ;
- lisible ;
- stable ;
- premium.

Ne pas essayer d'y faire entrer toute la complexité du marché.

La sophistication doit apparaître **après l'entrée dans l'expérience.**

Le header peut cependant participer au langage du monde :

- changement subtil de profondeur ;
- lumière ;
- état actif ;
- transition ;
- réaction au contexte.

Mais jamais au détriment de la navigation.

---

# XXIV. LE SITE EST UN SEUL ORGANISME

Les pages ne doivent pas sembler avoir été conçues séparément.

### Accueil

**COMPRENDRE**

Le marché, son territoire, sa logique, son fonctionnement.

### Acheter

**EXPLORER**

Chercher une offre et trouver une correspondance.

### Vendre

**ALIMENTER**

Ajouter une offre au réseau.

### Demander

**PROPAGER**

Exprimer une demande au réseau.

### Catégories

**COMPRENDRE LA STRUCTURE**

Explorer les familles de produits.

### Carte

**LOCALISER**

Comprendre la dimension territoriale.

### Prix du marché

**OBSERVER**

Comprendre l'évolution et la dynamique du marché.

Ces expériences doivent partager :

- typographie ;
- lumière ;
- profondeur ;
- physique ;
- langage du curseur ;
- langage des transitions ;
- principes de mouvement ;
- matière ;
- ambiance.

Mais chaque espace peut avoir sa propre personnalité.

---

# XXV. LA TRANSITION EST UN PASSAGE D'ÉTAT

Ne penser jamais :

> ancienne page → nouvelle page.

Penser :

> **état du marché → nouvel état du marché.**

Exemples :

Une exploration produit peut devenir une concentration autour d'une offre.

Une carte peut devenir un produit.

Une demande peut devenir une connexion.

Une connexion peut devenir une fiche.

Une donnée peut devenir une visualisation.

Utiliser :

- caméra ;
- zoom ;
- profondeur ;
- lumière ;
- blur ;
- particules ;
- displacement ;
- morphing ;
- masque ;
- révélation.

L'utilisateur doit avoir l'impression d'avoir **traversé un espace**, pas d'avoir changé brutalement de page.

---

Ne pas utiliser WebGL simplement parce qu'il est disponible.

---

# XXVII. WEBGL ≠ WEBGL PARTOUT

L'objectif n'est pas :

> « mettre du Three.js partout ».

L'objectif est :

> **utiliser la technologie la plus pertinente pour produire l'expérience la plus forte.**

Certaines zones peuvent être fortement immersives.

D'autres doivent rester sobres.

Une zone transactionnelle peut privilégier la précision.

Une zone narrative peut privilégier l'immersion.

Une zone de données peut privilégier la lisibilité.

La sophistication vient de la **bonne distribution de la complexité**.

---

# XXVIII. PERFORMANCE

La performance fait partie du design.

Le résultat doit sembler visuellement complexe tout en restant techniquement intelligent.

Toujours considérer :

- GPU efficiency ;
- draw calls ;
- instancing ;
- textures optimisées ;
- shaders raisonnables ;
- lazy loading ;
- progressive enhancement ;
- gestion intelligente du DPR ;
- densité adaptative ;
- pause des simulations hors écran ;
- nettoyage des ressources ;
- limitation des calculs par frame ;
- prefers-reduced-motion.

Ne pas supprimer la créativité pour gagner en performance.

**Optimiser l'illusion.**

Créer une sensation de monde complexe sans imposer une complexité inutile au navigateur.

### Accessibilité, robustesse et priorité aux actions

L’expérience doit rester compréhensible et fonctionnelle sans WebGL, sans animation et sans curseur personnalisé.

Les parcours essentiels — rechercher une offre, publier une offre, créer une demande et consulter les informations de marché — doivent rester rapides, accessibles et utilisables sur mobile, au clavier et avec une connexion limitée.

Respecter `prefers-reduced-motion`. Ne jamais imposer de défilement, de mouvement de caméra ou d’animation qui gêne la lecture, provoque un inconfort ou empêche l’utilisateur d’agir.

---

# XXIX. RÈGLE DATA → VISUALISATION

Ne jamais inventer :

- offres ;
- demandes ;
- connexions ;
- volumes ;
- prix ;
- activité ;
- tendances ;
- disponibilité.

Si la donnée n'existe pas, représenter honnêtement l'état vide.

Le WebGL doit visualiser le marché réel.

Il ne doit jamais fabriquer artificiellement un marché pour rendre l'interface plus spectaculaire.

Toute métaphore visuelle doit correspondre à une donnée ou à un état réel du système. Ne jamais suggérer une disponibilité, une activité, une connexion ou une tendance qui n’est pas confirmée par les données.

# XXXV. DIRECTIVE D'IMPLÉMENTATION

Avant de modifier le code :

1. Analyse l'architecture actuelle.
2. Analyse les données réellement disponibles.
3. Analyse le parcours utilisateur.
4. Identifie les incohérences UX.
5. Identifie les opportunités de motion.
6. Définis le langage physique du site.
7. Définis les états du système.
8. Définis les relations DOM ↔ WebGL.
9. Définis les transitions.
10. Puis seulement implémente.

Tu es autorisé à **restructurer profondément les compositions visuelles**, les espacements, les H1, les blocs, les proportions, les séquences et la hiérarchie lorsque cela améliore l'expérience.

Ne détruis cependant jamais :

- la logique métier ;
- les données existantes ;
- les actions essentielles ;
- la cohérence du produit.

### Critères de validation

Avant de considérer une expérience comme terminée, vérifier que :

- l’action principale est immédiatement compréhensible ;
- l’utilisateur peut accomplir son parcours sans attendre une animation ;
- les données représentées sont réelles et correctement qualifiées ;
- les contenus restent lisibles et accessibles sur mobile et au clavier ;
- l’expérience reste fonctionnelle avec les animations réduites ou désactivées ;
- chaque effet améliore la compréhension, l’orientation ou le retour d’interaction.

---

# XXXVI. OBJECTIF FINAL

Ne cherche pas à créer :

> **le site avec le plus d'effets.**

Cherche à créer :

> **le site dont chaque mouvement semble inévitable.**

La caméra bouge parce que l'utilisateur avance.

La lumière apparaît parce qu'une information devient importante.

Le brouillard recule parce que le focus change.

Les particules convergent parce qu'une connexion se forme.

La carte réagit parce que le territoire devient pertinent.

Le produit devient net parce qu'il devient la cible.

La demande se propage parce qu'elle cherche une offre.

L'offre s'illumine parce qu'elle est disponible.

Le prix change d'état parce que la donnée évolue.

Le curseur influence le monde parce que l'utilisateur agit dessus.

Le scroll transforme l'espace parce que l'utilisateur progresse.

Tout doit appartenir au même système.
